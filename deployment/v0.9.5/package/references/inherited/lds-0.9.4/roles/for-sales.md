# For sales · LDS 0.9.4 (v0.9.4-mp1)

หน้านี้ตอบว่า "พูดอะไรได้ ส่งอะไรออกไปได้ และของที่ส่งต้องหน้าตาแบบไหน" ไม่ต้องรู้เรื่องสีหรือโค้ด แต่สามอย่างข้างล่างคือสิ่งที่ลูกค้าจะเห็นก่อนเจอเรา

## 1. Link preview คือหน้าแรกของเรา (SOCIALFMT-01)

เมื่อคุณส่งลิงก์หน้าข้อมูลใน LINE, email หรือ X ผู้รับเห็นภาพ 1200 × 630 ที่ต้องมี: เส้นสี่สีบนขอบบน · แผงน้ำเงินของ Landometer · ประโยคว่า "จะเห็นอะไรเมื่อเปิด" · แหล่งข้อมูล วันที่ และข้อจำกัด · ที่อยู่ปลายทาง (ไม่ใช่ปุ่ม) ภาพเป็นภาพนิ่งเสมอ ถ้า preview ไม่มีของเหล่านี้ หน้านั้นยังไม่พร้อมส่ง — แจ้งทีม ไม่ต้องทำภาพเอง

ข้อความ preview จะเป็นแบบนี้เสมอ: **og:title** = `[สิ่งที่แสดง] [ช่วง/ขอบเขต] · [ผลิตภัณฑ์]` · **og:description** = `[จะเห็นอะไร] · [แหล่ง · วันที่] · [ข้อจำกัด]` ไม่มีเครื่องหมายอัศเจรีย์ ไม่มี "คลิกเลย" ไม่มี emoji ไม่มีตัวเลขที่ไม่มีหน่วย

## 2. EvidenceCard คือ "ใบรับรอง" ที่แนบไปกับตัวเลข (EVID-05)

เมื่อคุณอ้างตัวเลขจากระบบ ให้ส่ง EvidenceCard แทนการพิมพ์ตัวเลขลอย ๆ การ์ดมี: ค่า + หน่วย + สถานะ · dataset · แหล่ง · วันที่ · ขอบเขตพื้นที่ · ข้อจำกัด · ลิงก์ถาวร · เลขใบรับ ลูกค้าและ AI ของลูกค้าตรวจกลับได้ทุกช่อง ขอการ์ดจากทีมด้วยการระบุ claim id หรือหน้าข้อมูล; ห้ามแก้ตัวเลขหรือตัดข้อจำกัดออก

ข้อความสำรองแบบหนึ่งบรรทัด (เมื่อวางในแชท): `0 แห่ง · measured_zero · [dataset] · [แหล่ง] · [วันที่] · [ขอบเขต] · [ข้อจำกัด] · https://…/claims/[id] · receipt [id]`

## 3. ห้าคำที่ต้องพูดให้ถูก

| เห็นบนการ์ด/ตาราง | พูดว่า | ห้ามพูดว่า |
|---|---|---|
| 0 ศูนย์ (สำรวจแล้ว) | "สำรวจแล้ว ไม่พบ … (0 แห่ง)" | "ไม่มีข้อมูล" |
| — ไม่มีข้อมูล | "ยังไม่มีข้อมูลปีนี้ ล่าสุดคือปี …" | "เป็นศูนย์" หรือ "N/A" |
| นอกขอบเขต | "พื้นที่นี้อยู่นอกขอบเขตชุดข้อมูล" | "ไม่มีอะไรตรงนั้น" |
| ‹5 ปิดค่า | "ค่าต่ำกว่า 5 จึงปิดเพื่อคุ้มครองข้อมูล เปิดได้ที่ระดับ …" | ตัวเลขที่เดาเอง |
| … ยังไม่ถึงรอบ | "ข้อมูลรอบถัดไปคาดว่า …" | "ระบบยังไม่มี" |

ป้ายหลักฐานที่ใช้ได้มีหกแบบเท่านั้น (Master Brand Brief §3.7): ข้อเท็จจริงที่วัดได้ · การตีความเทียบ benchmark (ต้องบอกจักรวาลและขนาดกลุ่มเทียบ) · เจ้าของยืนยัน · ข้อสรุปของผู้เขียน · สมมติฐาน · หลักฐานจากหน้างาน

## 4. โลโก้ขยับและ motif ในเด็ค/คลิปที่ส่งลูกค้า

- เด็คและ PDF ใช้เฟรมสุดท้าย (ภาพนิ่ง) ของโลโก้และ motif เท่านั้น และวางตามตารางพื้น (MOTIF-06): ลายแบบ full บนสไลด์พื้นขาวหรือ beige, ลายแบบ quiet บนสไลด์พื้นน้ำเงินหรือพื้นเข้ม — ห้ามวาง full บนสไลด์น้ำเงินและห้ามแก้สีลาย; คลิปที่มีโลโก้ประกอบตัวหรือ product sting ต้องมาจากทีม (export จาก runtime ที่ลงทะเบียน) ไม่ตัดต่อเอง
- motif ไม่ใช่หลักฐาน: อย่าอธิบายลวดลายว่า "แสดงข้อมูลจริง" — ข้อมูลอยู่ที่ EvidenceCard
- ijji, CityChat มี sting ของตัวเองที่อนุมัติแล้ว; CityMETER, CityWiki ยังไม่มี (รอผลิต) — อย่าใช้ sting ของผลิตภัณฑ์หนึ่งแทนอีกผลิตภัณฑ์

## 5. สิ่งที่ออกนอกองค์กรไม่ได้ (Master Brand Brief v0.5.3)

- ราคา สัญญา pipeline และ SWOT ภายใน (รวมราคาคู่แข่ง)
- จำนวนผู้ทดลองใช้เป็น traction · LOI/ข้อเสนอ/test site เป็น "ลูกค้า" · ยื่นแล้วเป็น "อนุมัติแล้ว" · prototype เป็นผลลัพธ์สุดท้าย
- คำว่า SRI = รายได้ · heatmap = จำนวนคนเดิน · rating = ยอดขาย · ราคาที่ดิน = รายได้ผู้อยู่อาศัย · ทราฟฟิกสูง = โอกาสอาหารสูง
- ป้ายสถานะผลิตภัณฑ์นอกชุด MBB §5.1 (CityMETER, CityChat = เข้าสู่ตลาดระยะแรก · ijji = กำลังสร้างตลาด · CityWiki = ลงทุนเชิงกลยุทธ์ · งานตามสัญญา = สัญญาเดินอยู่ · ระบบข่าวกรองสินทรัพย์ = ดำเนินการจริงในเครือ)
- โลโก้ที่วาดใหม่ ภาพโลโก้ขยับที่ตัดต่อเอง หรือภาพทีมเป็นหลักฐานผลลัพธ์ผลิตภัณฑ์

## 6. เช็คลิสต์ก่อนกดส่ง

1. ลิงก์แสดง preview ที่มีแผงน้ำเงิน เส้นสี่สี และประโยค "จะเห็นอะไร" ไหม
2. ตัวเลขทุกตัวมาพร้อม EvidenceCard หรือลิงก์ถาวรไหม
3. มีคำว่า N/A, ราคา, สัญญา หรือ pipeline หลุดไปไหม
4. ผลิตภัณฑ์ที่พูดถึงใช้ป้ายสถานะตาม MBB ไหม
5. ถ้ายังไม่แน่ใจ ส่งเป็น internal preview ให้ทีมก่อน — งานที่ส่งลูกค้าต้องอ่านเหมือนงานที่เสร็จและตัดสินใจแล้ว
