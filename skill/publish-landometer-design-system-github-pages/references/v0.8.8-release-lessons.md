# v0.8.8 release lessons

## Authentication is a preflight, not a mystery state

Check `gh auth status -h github.com` and the active API user before publishing. Browser/device login is safe when the user completes it directly. If the one-time code expires, request a new one. Do not log out unless intentionally switching accounts, and never ask the user to paste a token into chat.

## Preserve the worktree

Inspect dirty files and branch state before changing anything. Fetch the current remote base and create a scoped branch from it. Stage exact allowlisted paths, inspect the cached name/status and whitespace checks, and preserve unrelated changes. Never use force push, hard reset, clean, automatic stash, or broad staging as a shortcut.

After a squash merge or branch divergence, compare patch content before replaying commits. Duplicate content should not be re-applied merely because commit SHAs differ.

## Repair CI narrowly

Open a draft PR, monitor every required check, and read the failed job log. Make the smallest fix that addresses observed evidence, then rerun the full local matrix before pushing. Mark ready and merge only when repository policy and required checks are satisfied.

## Bind proof to the deployed commit

A delayed verification workflow must check out the exact commit deployed by the Pages run. Manual dispatch requires an explicit commit. Derive expected source bytes from that commit after squash merge, then compare live HTML, manifest, standalone targets, fonts, images, favicon, registries, and evidence files byte-for-byte where the host does not transform them.

Record final URLs, redirects, media types, byte counts, SHA-256 values, and manifest parity. A green source build is not live proof.

## Keep immutable identities separate

- Design System version identifies the design-system release.
- Color Set or registry ID changes only when governed colors, gradients, token sources, or scale sources change.
- Artifact-build ID changes for every UI build, including UI-only fixes.
- QA evidence binds to the exact artifact build, hashes, state matrix, and manual-gate list.

When devices show different palettes, first compare immutable artifact URL/build ID, Color Set/registry/hash, source commit, bytes, and cache state. Treat mutable-root differences as build/cache skew until parity is proven.

## Standalone and identity delivery

Run a deterministic non-writing standalone rebuild before release. Validate immutable targets before replacing a mutable alias. A portable standalone must not claim a hosted canonical and must meet its declared offline contract.

The approved browser-tab symbol may use a stable absolute production URL in a standalone when that exception is recorded. Use a content-derived cache revision, verify MIME/dimensions/bytes/hash, and keep it separate from header, social-preview, touch, and maskable identity roles.

## Manual gates remain truthful

Compare gate IDs and statuses before and after the release. Removing, renumbering, or promoting a gate requires recorded evidence. Static presence of a gate file is not proof that the behavior passed.
