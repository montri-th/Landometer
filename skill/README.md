# Landometer reusable skill map

This catalog keeps reusable methods separate from version-locked and repository-specific work.

| Skill | Status | Layer | Use it for |
|---|---|---|---|
| `refine-landometer-experience` | active orchestrator | Landometer shared adapter | multi-area experience audits, implementation fixes, reusable-pattern routing, and normative-gap classification |
| `build-complete-design-system-color-atlas` | active reusable | product-neutral method | complete color inventory, exact specimens, analytical scales, responsive/accessibility QA, and build/hash parity |
| `shape-inspiring-design-system-guidance` | active reusable | product-neutral method | humanized bilingual learning, problem-first value proof, visual teaching, and constructive case galleries |
| `govern-web-identity-and-discovery` | active reusable | product-neutral web method | favicon/browser identity roles, social/SEO metadata, canonical routes, and bounded AI discovery |
| `publish-landometer-design-system-github-pages` | active release operator | repository-specific | explicitly authorized GitHub Pages publication, PR/CI closure, exact live verification, and release evidence |
| `apply-landometer-design-system-v0-9-0` | active authoring authority | version-locked | explicit v0.9.0 local application/audit against owner-approved authoring revision r1; copy the Appendix E Build Kit verbatim, run the `[SELFCHECK-01]` self-check, and keep generated machine-package conformance explicitly pending |
| `apply-landometer-design-system-v0-8-9` | frozen legacy | version-locked | explicit v0.8.9 historical application/audit only; do not silently upgrade an artifact or claim it represents v0.9.0 |
| `apply-landometer-design-system-v0-8-8` | frozen legacy | version-locked | explicit v0.8.8 historical application/audit only; do not silently upgrade an artifact or claim it represents v0.8.9 or v0.9.0 |
| `apply-landometer-design-system-v0-8-6` | frozen legacy | version-locked | explicit v0.8.6 local application or audit only |

## Recommended routing

```text
one focused concern
→ use the matching reusable skill
→ apply refine-landometer-experience when the artifact is Landometer-specific
→ publish-landometer-design-system-github-pages only after explicit publication authority
```

Do not silently upgrade `apply-landometer-design-system-v0-8-6`, `apply-landometer-design-system-v0-8-8`, or `apply-landometer-design-system-v0-8-9`; all three remain frozen legacy authorities for their named versions, and each keeps its own frozen Color Set (`color-srgb-01` for v0.8.8 and earlier, `color-srgb-02` for v0.8.9). `apply-landometer-design-system-v0-9-0` is the separate active **authoring-authority** skill for owner-approved revision `v0.9.0-r1` on Color Set `color-srgb-03`. It intentionally keeps generated tokens, recipes, schemas, fixtures, manifests, and preflight gated until they form one validated machine package, so neither the skill nor an artifact may claim v0.9.0 machine-package conformance yet.

## Scope boundary

Shared methods remain product-neutral across Land, Location, and Living. Product data, claims, voice, models, scores, permissions, and capabilities stay in the owning product layer. Cross-product, cross-place, or cross-city comparison requires a compatible schema and release or an explicit incompatibility statement.
