# Learning arc and case design

## Make value felt and visible

Use this sequence only as far as the lesson needs:

```text
recognisable moment of friction
→ consequence for a person or the next piece of work
→ credible possibility
→ one guided design move
→ visible AHA
→ one useful next action or clean completion
```

The opening can be emotional without being manipulative. Name lost context, hesitation, rework, ambiguity, missed action, or broken trust only when the fixture actually demonstrates it.

## Construct each case

Use:

```text
Intent
→ current context and evidence
→ design move
→ AHA the person can observe
→ value to the person or workflow
→ boundary or limitation
→ next action
```

Keep cases compact enough to scan. Let the user open the detailed rule, token, or rationale after the value is understood.

## Use a case quartet for broad guidance

When a section claims a pattern works across varied situations, show:

- three constructive cases with meaningfully different intents, work objects, or presentation forms;
- one rejected case that names the mismatch and shows the recovery.

Do not create four cosmetic variants of the same card. Diversity should come from the question or work, not decoration.

If a case uses a named product, dataset, place, event, or live capability, show its product scope, source, release, status, and limitation. A realistic fixture is not automatically a shared portfolio fact.

## Before and after

Keep object, facts, source, time, geography, and uncertainty fixed. The “after” may improve:

- the named decision and person;
- information order and emphasis;
- evidence, status, source, date, boundary, and limitation visibility;
- wording and tone;
- action choice and recovery;
- visual structure and accessible alternatives.

Never make the baseline unreadable, low-contrast, or broken just to make the design system look valuable.

## Invite participation

Use an action that lets people try the method on their own work: open a fixture, compare states, adapt a pattern, copy a governed recipe, or inspect the exact reference. Avoid vague “learn more” labels when the destination can be named.
